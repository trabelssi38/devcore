# Exécution du 2 octobre 2026 — portée des workflows

## Constat

- `GET /api/v1/workflows` listait tous les états de `DEV_CORE_DATA/Workflows` sans projet. `GET /api/v1/workflows/{run_id}` retournait un état sans vérifier son propriétaire. Le modèle persisté ne portait pas de projet.
- Contrôle en lecture seule du dossier actuel : **64 fichiers d'état**, **0 avec un projet**, **64 non attribués**, **0 JSON invalide**. Le nom et l'horodatage du fichier ne prouvent pas l'appartenance à un projet ; aucune attribution automatique n'a été effectuée.
- La métrique Prometheus exposait les noms de workflows comme labels globaux, avec une cardinalité dépendant du contenu métier.

## Changement

- Les deux routes workflows exigent `project`. Un état n'est retourné que si son champ `project` correspond exactement et si son `run_id` correspond au nom du fichier. Les identifiants de run dangereux sont refusés. Les états sans projet restent indisponibles par cette API jusqu'à leur réconciliation. Les lectures de fichiers passent dans le pool de threads FastAPI.
- `StateEngine` accepte et persiste désormais un projet explicite, y compris lors du chargement YAML et de la reprise JSON. Les états historiques non attribués restent lisibles par l'outil interne de reprise, sans devenir visibles dans l'API par défaut.
- `devcore_workflows_total` ne publie plus le nom du workflow ; il compte les états par statut valide. La route métriques exécute la lecture disque hors de la boucle asynchrone.
- OpenAPI et le client TypeScript ont été régénérés avec le paramètre `project` obligatoire.

## Génération du tableau de bord : tâches

- Cause vérifiée : `load_projects_and_tasks` réimportait automatiquement chaque `Memory/<projet>/tasks.json` dans SQLite à chaque génération. Un JSON Dropbox ancien pouvait donc écraser le statut `done` ou ressusciter une tâche `deleted` écrite par `TaskService`.
- La génération lit maintenant `DEVCORE_LOCAL_ROOT/devcore.db` en mode SQLite lecture seule. Elle ne crée plus de base, n'écrit plus dans la table `tasks` et ignore les tombstones `deleted`. Une base présente mais illisible provoque une erreur au lieu d'afficher silencieusement un JSON ancien.
- La lecture historique de `tasks.json` ne s'active qu'en l'absence de base locale avec `DEVCORE_DASHBOARD_LEGACY_JSON=1`. Ce mode ne fait aucun import vers SQLite ; il sert aux aperçus et à la transition explicite.
